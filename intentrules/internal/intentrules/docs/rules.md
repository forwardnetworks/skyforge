# Design-time intent rules

Generated by `go run ./cmd/intentrules docs` from `internal/intentrules/`. Do not edit by hand; a check fails when this page differs from the model.

The model is written in Infrahub's schema language (`schema/`, stock Infrahub YAML); what Skyforge adds lives in `sidecar/`. A Go evaluator reads a netlab topology before any compile, builds the objects the schema describes (with netlab's defaults filled in) and reports findings in the same shape as the compile's (`internal/netlabref`), with `source: intentrules`. netlab's own result wins: a code the compile already reported is not repeated.

| `constraint:NetlabP2pLink.endpoints:max_count` | `link-endpoints` | will-not-work | NetlabP2pLink | schema constraint `max_count` on `endpoints`: {name} is typed point-to-point but names {count} nodes; it needs two |
| `constraint:NetlabP2pLink.endpoints:min_count` | `link-endpoints` | will-not-work | NetlabP2pLink | schema constraint `min_count` on `endpoints`: {name} is typed or read as point-to-point but names {count} node(s); it needs two |
| `constraint:NetlabP2pLink.endpoints:required` | `link-endpoints` | will-not-work | NetlabP2pLink | schema constraint `required` on `endpoints`: {name} names no node |
| `constraint:NetlabPluginBlock.plugin:min_count` | `unknown-topology-attribute` | will-not-work | NetlabPluginBlock | schema constraint `min_count` on `plugin`: {key} is the configuration block of the {owner} plugin, which is not enabled (add it under plugin:) |
| `constraint:NetlabPluginBlock.plugin:required` | `unknown-topology-attribute` | will-not-work | NetlabPluginBlock | schema constraint `required` on `plugin`: {key} is the configuration block of the {owner} plugin, which is not enabled (add it under plugin:) |
| `constraint:NetlabStubLink.endpoints:cardinality` | `link-endpoints` | will-not-work | NetlabStubLink | schema constraint `cardinality` on `endpoints`: {name} is typed stub or loopback but names {count} nodes; it takes one |
| `constraint:NetlabStubLink.endpoints:required` | `link-endpoints` | will-not-work | NetlabStubLink | schema constraint `required` on `endpoints`: {name} names no node |
| `group-module-list-without-members` | `group-module-no-members` | will-not-work | NetlabGroup | A group carries a module list but nothing is a member of it: not its members list, not a node naming it, and no plugin that generates nodes is enabled. |
| `irb-vlan-ospf-on-vxlan-fabric` | `evpn-svi-ospf-overlay` | likely-wrong | NetlabVlan | An IRB VLAN, with OSPF left at netlab's default (on) or set on, that two or more nodes running ospf, vxlan and evpn carry. netlab puts OSPF on the SVI, the leaves adjoin across their own VXLAN tunnel and the fabric flaps. A VLAN that one node carries is a stub network: netlab makes its SVI passive, so nothing forms and the rule stays quiet. A hand-written topology leaves vlans.<name>.ospf absent, which is the default, so the rule fires on absent as well as on true. |
| `module-requires-module` | `module-requires` | will-not-work | NetlabDevice | A node enables a module whose required module it does not enable (evpn needs bgp, vxlan and stp need vlan). The requirement is read from netlab's own module definitions, never copied here. |
